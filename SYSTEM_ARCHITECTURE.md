# 📊 Product Analytics Platform: Technical Documentation

This document provides a deep dive into the architecture, data methodologies, and AI logic employed in both the **Passenger (Commuter)** and **Operator (Business)** analytics pipelines.

---

## 🏗️ 1. Dashboard Architecture (`app1.py`)

The dashboard is built on **Streamlit** and serves as the primary visualization layer. It follows a multi-tab structure to separate raw data, processed metrics, and AI-generated insights.

### Common Data Logic:
- **Deduplication**: Both pipelines use a deduplication script (`pipeline_deduplication.py` for passengers, `pipeline_business_deduplication.py` for operators) to remove ghost events caused by network retries.
- **Categorization**: Events are strictly separated into `application` (user-triggered) and `system` (background/automated) to ensure behavioral metrics aren't skewed by machine logs.
- **Sampling**: Advanced AI reports use **Sampling** (12% for passengers, 1.8% for operators) to maintain real-time reasoning speeds and manage LLM token limits while maintaining statistical significance.

## 🚍 2. Commuter Section (Passenger)

### A. Data Tab
- **Data Source**: `Commuter Users Event data.csv` (Deduplicated).
- **Methods**: Boolean filtering and column-wise sorting.
- **Logic**: Provides the "Ground Truth." Used to verify specific event payloads (like Search Queries) before they are aggregated into charts.

### B. Analysis Tab (Journey Flow)
- **Data Source**: Application events filtered by `user_uuid`.
- **Methods**: Time-sequence sorting and session splitting (using 30-minute idle gaps).
- **Logic**: Visualizes the **Human Timeline.** It identifies "Dead Ends" in the UI where passengers search for buses but never proceed to seat selection.

### C. Session Analysis Tab
- **Methods**: **System-Event Boundary Detection.** 
- **Logic**: Uses explicit system markers (App Start, Login) to define visit length. It employs a **Bounce Rate Algorithm** (% of sessions with < 2 events) to measure immediate abandonment. 
- **Recommendation Engine**: Employs a **Conditional Logic Layer** that maps high-exit events (e.g., `select_seat`) to specific UI interventions (e.g., "Simplify seat UI").

### D. Pattern Discovery Tab
- **Methods**: **Behavioral Clustering (DBSCAN)** & **Sequential Pattern Mining.**
- **Logic**: Clusters users into personas based on activity intensity and diversity. It uses **Transition Probability Matrices** to predict the likelihood of a user moving from "Search" to "Book" vs. "Exit."

## 🛠️ 3. Operator Section (Business)

### A. Operational Analytics Tab
- **Methods**: **Workflow Mapping Engine.**
- **Logic**: Re-maps raw event names (e.g., `hisab_page_loaded`) into high-level business categories like "Accounting" or "Route Management." This allows you to measure department-level efficiency rather than just raw clicks.

### B. Business Pattern Discovery
- **Methods**: **Intervention Trigger Logic.**
- **Logic**: Monitors for specific "Failure Sequences" (e.g., 3 consecutive failed logins). It identifies **Platform Stability** by tracking where staff encounter technical errors that block daily bus operations.

## 🤖 4. LangGraph AI Pipeline (AI Global Report)

The "Global AI Report" is generated by an autonomous multi-agent system built with **LangChain** and **LangGraph**.

### The Architecture:
1. **Orchestrator Node**: 
   - Receives the sampled dataset.
   - Computes top-level metadata (Date span, total users, peak hours).
   - Tasks 12 specialized agents to analyze specific metrics.
2. **Metric Agents (The 12 Specialists)**:
   - Each agent (e.g., *Retention*, *Segmentation*, *Friction*) works in a "ReAct" loop.
   - **Data Access**: They call specialized Python tools (`create_query_tools`, `create_retention_tools`) to query the raw CSV for precise numbers.
   - **Reasoning**: They use the LLM to interpret these numbers against industry benchmarks (e.g., "W1 retention of 20% is strong for travel apps").
3. **Compiler Node**:
   - Aggregates the 12 individual outputs.
   - Resolves conflicts between findings.
   - Generates a standalone, interactive HTML report with Plotly charts.

### Why this logic?
Traditional dashboards show **WHAT** happened (the numbers). This LangGraph pipeline explains **WHY** it happened and **HOW** to fix it, providing automated business intelligence that would otherwise take a data analyst hours to compile.
